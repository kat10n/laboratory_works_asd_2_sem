# Лабораторная работа 5. Графы. Алгоритм Краскала

## Описание

Реализация неориентированного взвешенного графа через матрицу смежности и алгоритма Краскала для поиска минимального остовного дерева (МОД). Язык реализации - C.

## Структура проекта

```
5_lab_graphs/
  src/
    struct.h      -- структура Edge (ребро: u, v, weight)
    kruskal.h     -- объявления функций
    kruskal.c     -- реализация алгоритма Краскала
    main.c        -- точка входа, CLI
    tests.cpp     -- юнит-тесты (Google Test)
    bench.cpp     -- бенчмарки (Google Benchmark)
  filestxt/
    input.txt     -- пример входного файла
  GraphKraskal/   -- сторонняя реализация на C# (для сравнения)
  CMakeLists.txt
```

## Алгоритм

Алгоритм Краскала строит МОД жадно: сортирует все рёбра по весу и добавляет ребро в дерево, если оно не создаёт цикл. Для проверки цикла используется структура данных Disjoint Set Union (DSU, система непересекающихся множеств).

Реализованные оптимизации DSU:

- Path compression в функции `find` -- при поиске корня все вершины на пути сразу присоединяются к корню, следующие вызовы работают быстрее.
- Union by rank в функции `unite` -- более глубокое дерево всегда становится родителем, дерево не вырождается в цепочку.

Теоретическая сложность: O(E log E), где E -- количество рёбер.

```bash

cmake -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Будут собраны три исполняемых файла:

- `build/main.exe` -- основная программа
- `build/my_test.exe` -- юнит-тесты

## Использование

```bash
# вывод результата в терминал
./build/main.exe -f filestxt/input.txt

# сохранить результат в файл
./build/main.exe -f filestxt/input.txt -o result.txt

# справка
./build/main.exe -h
```

Формат входного файла:

```
4
0 10 6 5
10  0 0 15
6   0 0  4
5  15 4  0
```

Первая строка -- число вершин N. Далее матрица смежности N x N. Значение 0 означает отсутствие ребра.

### Сравниваемые реализации

**KruskalMine** -- данная реализация. DSU с union by rank и path compression.

**KruskalSimple** -- аналог реализации из репозитория GraphKraskal (C#). DSU с path compression, но без union by rank: при объединении двух деревьев корень первого всегда становится дочерним к корню второго без учёта глубины.

Оба алгоритма используют одинаковую сортировку рёбер через qsort и получают на вход один и тот же случайно сгенерированный граф.

### Результаты

| Граф (N вершин) | KruskalMine, нс | KruskalSimple, нс | Mine быстрее на |
|---|---|---|---|
| 10 | 1046 | 1102 | 5% |
| 100 | 130936 | 144210 | 9% |
| 500 | 4715580 | 4189190 | -11% (шум) |
| 1000 | 16666773 | 18538051 | 10% |

Time и CPU time близки во всех замерах, что говорит об отсутствии значимых накладных расходов операционной системы во время измерений.

### Вывод

На малых графах (N = 10) разница незначительна, оба алгоритма работают менее 2 мкс. При N = 100 и N = 1000 реализация с union by rank стабильно быстрее примерно на 10%. Это объясняется тем, что без union by rank деревья DSU могут вырождаться в цепочки, и функция `find` обходит большее количество узлов.

На N = 500 KruskalSimple показал результат лучше -- это статистический шум, характерный для бенчмарков на случайных данных. При конкретном наборе рёбер деревья DSU в простой реализации могут оказаться достаточно плоскими, и разница в стратегии union не проявляется.

Рост времени при увеличении N соответствует теоретической сложности O(E log E): при переходе от N = 100 к N = 1000 (в 10 раз больше вершин, примерно в 100 раз больше рёбер) время растёт примерно в 127 раз, что согласуется с ожидаемым поведением.
