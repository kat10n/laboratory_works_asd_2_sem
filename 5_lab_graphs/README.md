# Лабораторная работа 5. Графы. Алгоритм Краскала

## Описание

Реализация неориентированного взвешенного графа через матрицу смежности и алгоритма Краскала для поиска минимального остовного дерева (МОД). Язык реализации - C.

```
  GraphKraskal/   - сторонняя реализация на C# (для сравнения)
  CMakeLists.txt
```

## Алгоритм

Алгоритм Краскала строит МОД жадно: сортирует все рёбра по весу и добавляет ребро в дерево, если оно не создаёт цикл. Для проверки цикла используется структура данных Disjoint Set Union (DSU, система непересекающихся множеств).

Реализованные оптимизации DSU:

- Path compression в функции `find` - при поиске корня все вершины на пути сразу присоединяются к корню, следующие вызовы работают быстрее.
- Union by rank в функции `unite` - более глубокое дерево всегда становится родителем, дерево не вырождается в цепочку.

Теоретическая сложность: O(E log E), где E -- количество рёбер.

## Бенчмарки

### Что измеряется

Запускаются два бенчмарка из одного `bench.cpp` через Google Benchmark:

| Бенчмарк | Что вызывает |
|---|---|
| `BM_Kruskal_C` | `kruskal()` из `src/kruskal.c` (ваш код) |
| `BM_Kruskal_CS` | логика `KruskalMSTCompute()` из `GraphKraskal/Graph.cs`, портированная на C++ |

C# код портирован в `bench.cpp` напрямую, чтобы избежать overhead запуска .NET процесса - замер нечестный иначе.

### Запуск

**CLion:** Run -> **`my_bench`**.

```bash
cmake-build-debug\my_bench.exe
```

> Собирайте **Release** (`cmake -DCMAKE_BUILD_TYPE=Release`), иначе время завышено и появится предупреждение `Library was built as DEBUG`.

### Различия реализаций

| | `kruskal.c` (ваш) | `Graph.cs` (GitHub) |
|---|---|---|
| Хранение графа | матрица смежности `int**` | `List<Edge>` строится при создании графа |
| DSU: path compression | рекурсивный `find` | рекурсивный `Find` |
| DSU: union by rank | `rank[]`, три ветки | просто `parent[xRoot] = yRoot` |
| Сортировка | `qsort` на каждый вызов | копия `List<Edge>` + `Sort()` на каждый вызов |
| Аллокации в вызове | `malloc/free` на массив рёбер | `new List<Edge>` + `new int[n]` (GC heap) |

**Почему C быстрее:** union by rank снижает глубину дерева DSU; `qsort` на стеке-аллоцированном массиве быстрее heap-аллокации C# `List`. На N=1000 разница - **3×**.
